/goal Make Rezn a reliable local Docker controller through the existing Orqos API: validated signed intent must converge across updates, removals, failures, and restarts, with truthful status and repeatable acceptance tests.

Scope
Work in ~/dev/rezn. Inspect current code before implementing; use ../orqos as an API reference, without modifying it or other sibling repositories. Keep this an MVP: straightforward replacement is sufficient; downtime and changing dynamically assigned ports are acceptable. Defer Kubernetes, Podman certification, rolling updates, automatic image pulls, metrics/UI work, dependency upgrades, and signer trust/replay protection. Preserve the signed program envelope. Do not add compatibility aliases, automatic legacy migration, or implicit adoption. The user handles commits, pushes, and merges.

Starting evidence
- rezn-runtime/src/reconcile.rs compares only running replica counts. Image/port changes, removed pod instructions, and stopped containers are not reconciled; mutation failures are logged but the pass still succeeds.
- routes/apply.rs persists intent before executable validation. Unsupported kinds and env/secure fields are ignored later; desired state and instruction metadata are written separately.
- routes/state.rs exposes desired intent only and conceals corrupt JSON as an empty map. The live smoke test writes sled directly, bypassing signed /apply and runtime startup.
- Orqos GET /docker/containers supports all=true and label filters; its response includes Id, Labels, Image, State, and Ports. Rezn currently reads only Id/Names. The create response echoes requested host:0, so obtain allocated ports from subsequent observations.

1. Accept only executable intent
Define and document the supported subset: pod instructions with image, replicas, and TCP ports. Verify the canonical submitted program without dropping signed fields. Reject invalid signatures, unsafe/empty names, duplicate pod names, invalid images/ports, unknown fields/options, and unsupported kinds or env/secure fields with useful 4xx responses. Do not strip unsupported fields to make examples work: provide an explicitly supported signed example. Invalid submissions must change neither stored state nor containers. Atomically persist desired intent and metadata. A signed empty program replaces that deployment with no workloads; replicas=0 remains valid. An accepted response means stored intent, not completed deployment.

2. Converge the full owned lifecycle
Persist an unambiguous runtime ownership identity and validate ownership from labels before mutation; never infer ownership from name prefixes alone. Observe running and stopped owned containers, including workloads removed from desired intent. Fail before any mutation when desired-state validation or required observation fails; corrupt/unreadable state must never become an empty deletion plan.
Track a workload configuration identity that excludes replica count. Replace containers when image or ports change; unchanged reapplication preserves identities. Scale, clean up removed workloads, recover from stopped/failed-start containers, and avoid accumulating debris. Use container IDs for mutations, propagate failures, and retry safely on later passes. Restarting against the same database must preserve ownership and converge without duplicates. Serialize reconciliation, trigger it after apply, retain periodic recovery, and prevent an older pass from being reported as convergence of newer intent. Leave existing unproven resources untouched; document ownership/state format changes explicitly.

3. Report observable outcomes
Keep /state as desired intent; return an error for corrupt persisted state. Add a documented status API showing desired/current configuration, desired/running replica counts, container IDs/states, observed host IP/port mappings, last observation, and convergence errors. Backend failures must report unknown/stale observations rather than invented zero counts or success. Read Ports from container listings, including after restart. Update OpenAPI, the actual reznctl usage example, and lean development/status documentation; replace unsupported README claims with verified behavior.

Acceptance
Add focused tests for validation atomicity, updates/removals, ownership isolation, failed observations and mutations, corrupt state, restart recovery, and stale status. Extend live acceptance to use signed HTTP /apply through a real Rezn process and Docker-only Orqos: create, reapply, scale 1→2→1→0, change image/ports at equal replica count, remove one pod, apply an empty program, restart, and recover after backend failure. Verify a nonzero published port serves HTTP, stable identities for unchanged workloads, no stopped leftovers, and untouched foreign containers. Use isolated databases/keys, bounded waits, an explicit Docker context, pre-pulled test images, and cleanup after failures. Never stop Docker Desktop or prune unrelated resources.

Run cargo fmt --check, cargo build --locked --workspace, cargo test --locked --workspace, and cargo clippy --locked --workspace --all-targets. Keep existing regressions passing; separate pre-existing warnings. Document one reproducible acceptance command and run it locally. Keep ordinary tests in push/PR CI; make live prerequisites explicit. Finish with changed behavior, validation results, and remaining limitations; do not commit or merge.

Follow-up
Signature verification currently trusts a public key supplied by the caller, does not bind the deployment name, and has no replay protection. Document these limits; address trusted signers and a signed deployment/revision contract before expanding beyond local development. Inspect any DSL signing/verifying discrepancies separately, without changing its repository in this goal.
