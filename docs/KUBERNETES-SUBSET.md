# Supported Kubernetes subset

Status: specification for M0 ([#82](https://github.com/rezn-project/rezn/issues/82)). The import that applies it
is [#83](https://github.com/rezn-project/rezn/issues/83).

Rezn imports rendered Kubernetes manifests (for example `helm template` output) into [IR v2](IR-v2.md). It accepts
exactly the subset below, derived from what the reference workload's chart uses in both of its profiles and
nothing more. **Every kind, field and value not listed is rejected** with its JSON pointer; nothing is ignored
silently except the fields marked *ignored* here.

The machine-readable definition is [`spec/kubernetes-subset.json`](../spec/kubernetes-subset.json). Check
manifests against it with:

```sh
helm template … | scripts/k8s_subset_check.py -     # exit 1 and one line per violation
```

The tables at the end are generated by `scripts/k8s_subset_check.py --markdown`; `scripts/test_spec.py` fails
when they are stale, and requires [`spec/testdata/kubernetes-valid.yaml`](../spec/testdata/kubernetes-valid.yaml)
to exercise every rule.

## Kinds

| Kubernetes | IR v2 |
| --- | --- |
| Deployment (`Recreate`) | `replica_set` |
| StatefulSet | `ordered_replica_set` |
| Job | `job` |
| CronJob | `scheduled_job` |
| Service (ClusterIP, headless) | `service` |
| Ingress | `ingress` |
| NetworkPolicy | `network_policy` |
| ConfigMap | `config` |
| Secret (`Opaque`, `kubernetes.io/tls`) | `secret` |
| PersistentVolumeClaim (`ReadWriteOnce`) | `volume_claim` |

## Dispositions

- **supported**: imported with Kubernetes semantics.
- **constrained**: only the listed values are accepted (for example `capabilities.drop: [ALL]`, no `add`).
- **ignored**: accepted and not carried into IR v2, for the stated reason.

## Translation rules

**Selectors become names.** A Service `selector`, a NetworkPolicy `podSelector` and a `podSelector` peer must
match the template labels of exactly the workloads they name (a Service: exactly one; a policy: at least one) in
the same set of manifests. Import resolves them to workload names and fails when a selector matches nothing, or
more than one workload for a Service. Workload `selector.matchLabels` must be a subset of the template labels.
Labels are not carried into IR v2.

**Quantities become integers.** CPU `100m` → `100`, `1` → `1000`, `1.5` → `1500` millicores (at most three
decimals). Bytes accept the decimal suffixes `k`, `M`, `G`, `T` and binary `Ki`, `Mi`, `Gi`, `Ti`; `256Mi` →
`268435456`. Fractions of a byte are rejected.

**Init containers with `restartPolicy: Always` are sidecars.** They move to `pod.sidecars`, keep their order and
their `startupProbe`. Other init containers may not have probes.

**Every `emptyDir` needs a `sizeLimit`.** It becomes a pod-lifetime `scratch` volume (`medium: Memory` →
`memory`, otherwise `disk`), shared by all containers of the pod.

**Helm hooks become phases.** `helm.sh/hook` maps to `phase.when` (`pre-*` → `before`, `post-*` → `after`) and
`phase.on` (`install`, `upgrade`); `helm.sh/hook-weight` to `phase.weight`; `before-hook-creation` is Rezn's
behaviour for phased jobs. A hooked resource that is not a job is created when its phase first runs and is left
unchanged by later revisions that do not include its phase, as Helm does.

**Rendered Secrets are seeded once.** A Secret in the manifests becomes a `secret` with `source: {"seed_once": {}}`
and its keys; import writes the values to Rezn's secret store only if they are not there yet, and they never enter
the signed program. Re-rendering a chart that generates random values therefore keeps the first values, which is
what charts using Helm `lookup` intend. Secrets created by the operator are only referenced by name and must exist
in the store.

**Kubernetes defaults are written explicitly**, because Podman's differ: `terminationGracePeriodSeconds` 30,
probe period 10 s, timeout 1 s, failure threshold 3, `restartPolicy` Always, and `imagePullPolicy` Always for
`:latest` or untagged images, otherwise IfNotPresent.

**Namespace.** Manifests carry no `metadata.namespace`; the IR v2 namespace comes from the import command.
